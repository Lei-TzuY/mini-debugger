# Architecture

`lowlevel::ptrace` is the syscall boundary. It owns errno-sensitive `PTRACE_PEEKDATA`, register access, resume operations, byte patching, `PTRACE_ATTACH`, and `PTRACE_DETACH`.

`Process` owns the traced PID, origin (`Launched` or `Attached`), and lifecycle (`Running`, `Stopped`, `Exited`, `Signaled`, `Detached`). Launch uses `PTRACE_TRACEME`, waits for the post-`exec` `SIGTRAP`, then enables `PTRACE_O_EXITKILL`. Attach uses `PTRACE_ATTACH` and waits for the resulting `SIGSTOP`, but deliberately does not enable `PTRACE_O_EXITKILL`: an attached process is externally owned and must survive debugger teardown.

`Debugger` owns semantic execution state: last stop reason, breakpoint table, original instruction bytes, IDs, and the optional pending breakpoint step-over address. Non-`SIGTRAP` stops are represented as signals and the caller explicitly chooses suppression or forwarding.

Before detaching an attached process, `Debugger` restores every installed debugger-owned `INT3`. A breakpoint that is currently pending step-over is already restored when the breakpoint trap is classified, with RIP rewound to the original instruction. Explicit detach clears breakpoint ownership and transitions the process to `Detached`. Destructor cleanup follows the same restore-and-detach path for a stopped attached process; launched processes retain the existing kill-on-debugger-destruction behavior.

`ElfFile` is an independent parser/resolver. It validates ELF64/x86-64/little-endian headers, reads `SHT_SYMTAB` and `SHT_DYNSYM` directly, and resolves symbols without libbfd/libelf/debugger libraries. ET_DYN load bias is derived from the tracee's offset-zero mapping for that ELF file's canonical path and the ELF's zero-offset PT_LOAD virtual address; this is shared by PIE executables and mapped shared objects. ET_EXEC symbols use their linked virtual addresses directly.

`DwarfLineTable` is intentionally narrower than a general DWARF reader. It locates an uncompressed `.debug_line` section in ELF64, accepts bounded 32-bit-format DWARF v4 line-table units, executes their line-number VM, and converts emitted rows into half-open virtual-address ranges. Runtime address lookup subtracts `ElfFile`'s load bias. Reverse file:line lookup scans the same ranges, returns the lowest matching virtual address, and rejects basename ambiguity across distinct source paths; runtime reverse lookup then applies the existing ELF load bias. Unsupported DWARF versions, DWARF64, compressed line sections, and v4 multi-operation instruction tables fail explicitly rather than being interpreted heuristically.

`EhFrame` is a bounded CFI reader shared by `finish` and multi-frame `bt`. It locates an uncompressed `.eh_frame`, follows 32-bit CIE/FDE links, accepts CIE version 1 `zR` records whose FDE pointers use `DW_EH_PE_pcrel | DW_EH_PE_sdata4`, and evaluates the common x86-64 CFA location, offset, register, and remember/restore-state opcodes required by the fixture toolchain. Runtime RIP is converted back to the selected module's virtual address through that `ElfFile` load bias before selecting an FDE. Unsupported augmentation strings, pointer encodings, opcodes, malformed records, or unreadable slots throw instead of falling through to a guessed result.

For live current-frame recovery, `EhFrame::caller_return_address` can evaluate CFA against the complete ptrace general-purpose register set. For iterative backtraces, `EhFrame::caller_frame` consumes a read-only cursor containing RIP, RSP, and an optional recovered RBP. It sets caller RSP to the computed CFA, reads caller RIP through the CIE return-register offset rule, and recovers caller RBP only when the active CFI rule explicitly marks it as same-value or CFA-relative memory. A later FDE that requires some other unrecovered register fails explicitly; the unwinder never invents a register value.

`unwind::cfi` owns file-backed module routing for CFI. It resolves a RIP against `/proc/<pid>/maps`; ordinary absolute file-backed mappings are paired with that module's `ElfFile + EhFrame`, while caller-provided executable objects are reused when the mapping names the same file. `module_caller_return_address` applies this routing once to the current live register set for `finish`. Multi-frame `unwind_eh_frame` applies the same decision before every frame transition and caches shared-module parsers for the duration of the unwind. Anonymous mappings, deleted mappings, modules without `.eh_frame`, or frames without matching FDEs return no frame information; parse/evaluation failures remain explicit. A hard frame limit and strictly increasing caller RSP prevent malformed/self-referential walks.

`source::step_source` is a bounded orchestration layer above `Debugger` and `DwarfLineTable`; it does not own ptrace state. It records the current mapped file:line, repeatedly calls the existing `Debugger::single_step()`, and stops when the mapped file or line changes. Pending software-breakpoint displacement and reinsertion therefore remain owned by `Debugger`. If the tracee exits, receives a signal, or otherwise produces a non-single-step stop, source stepping returns that stop immediately. An instruction-count hard limit prevents infinite stepping through unmapped code.

`source::next_source` extends the same orchestration without adding a second breakpoint mechanism. At each instruction on the starting source line it recognizes the canonical x86-64 direct near-call byte `E8`; because that encoding is five bytes long, it installs a normal managed temporary breakpoint at `RIP + 5` and continues through the callee. On return it removes only that temporary breakpoint and resumes source-line comparison. An existing user breakpoint at the return address is never replaced or removed, and any breakpoint/signal/exit encountered before return is surfaced immediately after cleaning up an owned temporary breakpoint. Indirect or prefixed call encodings are intentionally outside this bounded first `next` slice and therefore fall back to ordinary instruction stepping.

`source::finish_frame` is frame-oriented and independent of `.debug_line`. It resolves the tracee's main executable only as the preferred module, then delegates current-RIP module selection to `unwind::cfi`; a stopped instruction inside an ordinary shared object therefore uses that shared object's `.eh_frame` and load bias. If no file-backed module CFI applies, it falls back to the older validated RBP frame record. Unsupported or malformed selected CFI is an explicit error rather than a reason to silently trust RBP. Once a return address is known, finish installs a normal managed temporary breakpoint there unless a user breakpoint already exists.

`unwind::frame_pointer` remains the deterministic fallback strategy. It seeds the trace from stopped RIP/RBP, reads `{previous_rbp, return_address}` pairs from tracee memory, requires the RBP chain to move monotonically toward higher stack addresses, caps each frame jump and the total frame count, and returns a partial trace with an explicit stop reason when memory is unreadable or the chain is malformed. The CLI uses this fallback only when the starting RIP has no applicable file-backed CFI.

On a managed `SIGTRAP`, `Debugger` checks `RIP - 1` against installed breakpoints, rewinds RIP, restores the original byte, and marks the breakpoint temporarily uninstalled. The next `continue` or `stepi` executes exactly one original instruction and reinstalls `INT3` only if the breakpoint still exists. Source breakpoints are resolved to a runtime address before entering this same breakpoint state machine; source `step`, `next`, and frame `finish` delegate to it rather than introducing parallel ptrace state.

Current limits: one traced process/thread, x86-64 Linux only, DWARF source mapping/source breakpoints/source stepping limited to v4 `.debug_line`, and source `next` only recognizes canonical `E8 rel32` direct calls. CFI backtraces and current-frame `finish` can route across ordinary file-backed modules but still use only the bounded CIE/FDE encoding/opcode subset above; iterative frames can use recovered RSP/RBP/RIP but not arbitrary reconstructed registers. Source mapping and CLI symbolization remain main-executable-oriented. Hardware watchpoints, DWARF5 line tables, broad `.eh_frame` encoding/opcode coverage, and a general instruction decoder remain future work.
